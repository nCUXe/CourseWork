# Отчёт о вычислительном эксперименте
## Исследование точности приближённого алгоритма для многомерной целочисленной задачи о ранце

---

## 1. Постановка задачи

Исследуется **многомерная целочисленная задача о ранце**:

```
max cx,   x ∈ Z+^n,   Ax ≤ b
```

- `n` — число типов предметов, `m` — число ресурсных ограничений
- `A[j][i]` — расход ресурса j на одну единицу предмета i
- `b[j]` — ёмкость ресурса j,  `c[i]` — прибыль от единицы предмета i
- Переменные `x[i] ∈ {0, 1, 2, ...}` — количество единиц предмета i

Задача **NP-сложная**, поэтому практический интерес представляют приближённые алгоритмы.

---

## 2. Исследуемый алгоритм

Рассматривается алгоритм из статьи **Чиркова А.Ю. и Золотых Н.Ю.**

**Идея:** для каждого типа предмета j вычислить, сколько его можно взять при полном заполнении ранца только этим предметом, и выбрать наиболее выгодный вариант.

**Формула:**
```
u_j  = min_{i: A[i][j] > 0}  floor(b[i] / A[i][j])   — максимум единиц предмета j
j*   = argmax_j { c[j] · u_j }                        — лучший предмет
x[j*] = u_{j*},   x[i] = 0  для i ≠ j*               — решение
```

**Сложность:** O(n·m) — принципиально быстрее точных методов.

**Теоретическая гарантия (из статьи):**
```
α_mn = α_{1q} / (m + r·(α_{1q}/α_{1,q+1} − 1)),   n = m·q + r
```
При n → ∞: α_mn → 0.5914/m. Это нижняя граница — в худшем случае алгоритм даёт не менее ~59%/m от оптимума.

## 3. Что реализовано

| Модуль | Что делает |
|--------|-----------|
| `src/generator.py` | Генерация случайных задач с заданными характеристиками |
| `src/greedy.py` | Алгоритм из статьи (O(n·m)) |
| `src/exact.py` | Точное решение методом ДП с мемоизацией (ground truth) |
| `src/metrics.py` | Коэффициент приближения, зазор |
| `src/experiment.py` | Оркестрация серий экспериментов |
| `src/visualization.py` | Графики по результатам |

**Схема работы:**
```
config.py → 216 конфигураций
   ↓ для каждой (5 экземпляров)
generator → задача (A, b, c)
   ↓
greedy.py → приближённое решение x_G
exact.py  → оптимальное решение x_OPT  (ДП)
   ↓
ratio = profit(x_G) / profit(x_OPT) ∈ (0, 1]
   ↓
CSV + графики
```

## 4. Параметры эксперимента

| Параметр | Значения | Смысл |
|----------|----------|-------|
| n | 5, 6, 7, 8, 9, 10 | Число типов предметов |
| m | 1, 2, 3 | Число ресурсных ограничений |
| density | dense, sparse | Плотность матрицы A |
| profit_type | random, correlated, anticorrelated | Связь прибыли с весами |
| alpha | 0.3, 0.8 | Тугость ограничений (b[j] = floor(α · ΣA[j])) |

**Итого: 216 конфигураций × 5 экземпляров = 1080 экспериментов**

## 6. Выводы

### Найденный подкласс эффективности

**Алгоритм наиболее эффективен при m = 1 (одно ресурсное ограничение).**

- Средний ratio при m=1: **0.989** (практически оптимален)
- Минимальный ratio при m=1: **0.954** (никогда не хуже 95.4%)
- Причина: при одном ограничении задача одномерная, и единственный предмет взятый в максимальном количестве часто является оптимальным (смешение нескольких предметов редко даёт значительный выигрыш)

**Дополнительные факторы улучшающие ratio:**
1. **dense-матрица** (+8.5% к ratio относительно sparse): каждый предмет "чувствует" все ресурсы, алгоритм лучше оценивает реальную стоимость
2. **Жёсткие ограничения (alpha=0.3)**: меньше предметов помещается, решение "одного предмета" с большей вероятностью совпадает с оптимальным
3. **Малое n**: при n=5, m=1 ratio=1 на всех тестах (оптимум достигается всегда)

### Объяснение ухудшения при m > 1

При m=3, sparse, random, n=8: min_ratio = 0.396

Причина: разреженная матрица создаёт предметы с разными "профилями" потребления ресурсов. Оптимальное решение выгодно использует эти профили через смесь предметов. Алгоритм же выбирает лишь один тип — именно этот случай является "adversarial" для алгоритма.

### Соответствие теории

Теорема из статьи Чиркова–Золотых предсказывает:
- Гарантированная точность α_{mn} монотонно убывает с ростом m и n
- lim α_{mn} = α_{1∞}/m ≈ 0.5914/m

Эксперимент подтвердил тренд: avg_ratio для m=3 (~0.83) лучше теоретической нижней границы (0.59/3 ≈ 0.197), что ожидаемо — граница достигается лишь на специально сконструированных задачах, а не на случайных.
