# Вычислительный эксперимент: жадный алгоритм в задаче о рюкзаке

Дипломная работа, посвящённая исследованию качества жадного (greedy) алгоритма как приближённого метода решения многомерной (многоограничительной) задачи целочисленного рюкзака. Проект автоматизирует процесс генерации тестовых задач, запуска алгоритмов, вычисления метрик приближения и построения аналитических графиков.

---

## Постановка задачи

### Многомерная целочисленная задача о ранце

> Источник: А.Ю. Чирков, Н.Ю. Золотых. «О приближённом алгоритме решения многомерной целочисленной задачи о ранце».

Дана совокупность:
- **n** типов предметов
- **m** ресурсных ограничений
- Матрица **A ∈ Z+^{m×n}**, где `A[j][i]` — расход ресурса j на одну единицу предмета i
- Вектор **b ∈ Z+^m**, где `b[j]` — ёмкость ресурса j
- Вектор **c ∈ Z+^n**, где `c[i]` — прибыль от одной единицы предмета i
- Переменные `x[i] ∈ Z+` — сколько единиц предмета i взять (0, 1, 2, ...)

### Целевая функция

Максимизировать общую прибыль:
```
max cx = max Σ(i=1 to n) c[i] · x[i]
```

При ограничениях:
```
x ∈ L(A, b) = { x ∈ Z+^n : Ax ≤ b }
```

то есть: `Σ(i=1 to n) A[j][i] · x[i] ≤ b[j]`  для всех j = 1..m

### Отличие от задачи 0–1

В задаче 0–1 каждый предмет берётся не более одного раза: `x[i] ∈ {0, 1}`.
В **целочисленном** варианте каждый тип предмета можно взять **любое неотрицательное** целое количество раз.

### Сложность

Задача является **NP-сложной** уже при m=1. С ростом m и n точное решение становится вычислительно неприемлемым. Гарантированная точность приближённого алгоритма α_mn исследована в указанной статье.

---

## Рассматриваемые алгоритмы

### 1. Приближённый алгоритм (статья Чиркова–Золотых)

**Идея (из статьи):** для каждого типа предмета j определить точку v_j из L(A, b) — решение, в котором берётся только предмет j в максимально возможном количестве. Из всех таких точек выбрать ту, что даёт наибольшую прибыль.

**Максимальное количество единиц предмета j (при взятии только его):**
```
u_j = min_{i: A[i][j] > 0} floor(b[i] / A[i][j])
```

**Ценность точки v_j:**
```
cv_j = c[j] · u_j
```

**Приближённое решение:**
```
j* = argmax_j { c[j] · u_j }
x[j*] = u_{j*},  x[i] = 0  для i ≠ j*
```

**Алгоритм:**
1. Для каждого предмета j вычислить u_j и ценность c[j] · u_j
2. Выбрать предмет j* с максимальной ценностью
3. Вернуть решение: взять u_{j*} единиц предмета j*, остальные — 0

**Сложность:** O(n · m) — для каждого из n предметов проверяем m ресурсных ограничений.

**Гарантированная точность:** значение α_mn = α_{1q} / (m + r(α_{1q}/α_{1,q+1} − 1)), где n = mq + r (теорема из статьи). При больших n/m: α_mn ≈ α_{1n}/m, где lim α_{1n} ≈ 0.5914.

---

### 2. Точное решение (Динамическое программирование)

**Идея:** ДП по оставшимся ёмкостям ресурсов. Состояние — кортеж оставшихся ёмкостей; переход — взять одну единицу любого подходящего предмета.

**Рекуррентное соотношение:**
```
dp(r) = max_{j: A[:,j] ≤ r} ( c[j] + dp(r − A[:,j]) )
dp((0,...,0)) = 0
```
где r = (r_0,...,r_{m-1}) — вектор оставшихся ёмкостей.

**Алгоритм (top-down с мемоизацией):**
1. Рекурсивно вычислить dp(b) с кешированием по словарю memo[tuple(r)]
2. Восстановить решение: трассировка через memo из состояния b вниз

**Сложность:** O(n · ∏ b[j]) в худшем случае.

**Применение в эксперименте:** точное решение служит **эталоном (ground truth)** для вычисления коэффициента приближения. Применимо при малых значениях b (достигается параметром MAX_WEIGHT=5 в config.py).

## Основные компоненты

### [models.py](src/models.py)

**`KnapsackInstance`** — представление одной задачи о рюкзаке:
- `n: int` — количество предметов
- `m: int` — количество ограничений
- `A: List[List[int]]` — матрица потребления ресурсов размером m × n
- `b: List[int]` — вектор ёмкостей ресурсов размером m
- `c: List[int]` — вектор прибылей размером n
- Методы валидации и вспомогательные функции

**`KnapsackSolution`** — решение задачи:
- `algorithm_name: str` — имя алгоритма ("greedy" или "exact_dp")
- `x: List[int]` — вектор количеств длины n: `x[i]` = сколько единиц предмета i взято
- `total_profit: int` — общая прибыль решения
- `used_resources: List[int]` — использованные объёмы каждого ресурса
- `is_feasible: bool` — допустимо ли решение (соблюдены все ограничения)

---

### [generator.py](src/generator.py)

Генерирует случайные экземпляры задач о рюкзаке с контролируемыми характеристиками.

**`generate_instance(n, m, density, profit_type, alpha, seed)`**

Параметры:
- `n` — количество предметов
- `m` — количество ограничений
- `density` — плотность матрицы A ("dense" или "sparse"). "sparse" означает, что часть элементов матрицы обнулена случайно.
- `profit_type` — тип генерации прибылей:
  - `"random"` — прибыли не коррелируют с потреблением ресурсов (нейтральный случай)
  - `"correlated"` — высокоприбыльные предметы требуют много ресурсов (благоприятный случай для жадного)
  - `"anticorrelated"` — высокоприбыльные предметы требуют мало ресурсов (сложный случай для жадного)
- `alpha` — коэффициент тугости ограничений (0 < α ≤ 1):
  - α = 0.3 — жёсткие ограничения (мало места для предметов)
  - α = 0.8 — мягкие ограничения (много места)

Процесс:
1. Генерируется матрица A (целые случайные числа, затем опционально прореживается)
2. Вычисляются ёмкости: `b[j] = max(1, floor(α · Σ(i) A[j][i]))`
3. Генерируются прибыли в зависимости от profit_type

---

### [greedy.py](src/greedy.py)

Реализует приближённый алгоритм из статьи Чиркова–Золотых. Функция `solve_greedy(instance)` вычисляет `u_j = max_count_for_item(j)` для каждого предмета, выбирает j* = argmax(c[j] · u_j) и возвращает `KnapsackSolution` с `x[j*] = u_{j*}`.

---

### [exact.py](src/exact.py)

Реализует точное решение методом динамического программирования (top-down с мемоизацией). Функция `solve_exact_dp(instance)` заполняет таблицу `memo[tuple(remaining)] = max_profit` и восстанавливает решение трассировкой. Возвращает `KnapsackSolution` с максимальной прибылью.

---

### [metrics.py](src/metrics.py)

Вычисляет метрики качества приближения:

- **`approximation_ratio(greedy_profit, exact_profit)`** — отношение `R = greedy_profit / exact_profit`
  - Всегда R ≤ 1 (жадный ≤ оптимум)
  - R близко к 1 → хорошее приближение
  - R близко к 0 → плохое приближение

- **`profit_gap(exact_profit, greedy_profit)`** — абсолютный зазор `Δ = exact_profit - greedy_profit`
  - Показывает, на сколько единиц жадный отстаёт от оптимума

- **`relative_profit_gap(exact_profit, greedy_profit)`** — относительный зазор `δ = Δ / exact_profit`
  - Процентное выражение: `δ · 100%` — на сколько процентов жадный хуже оптимума

- **`is_solution_feasible(instance, solution)`** — проверка допустимости решения

---

### [experiment.py](src/experiment.py)

Определяет логику проведения экспериментов.

**`ExperimentConfig`** — параметры одной серии экспериментов:
- `n, m, density, profit_type, alpha` — параметры генерации
- `num_instances` — количество экземпляров задач для этой конфигурации

**`run_single_experiment(config: ExperimentConfig, instance_id: int)`** — запуск одного эксперимента:
1. Генерирует один экземпляр задачи
2. Запускает жадный алгоритм
3. Запускает точный алгоритм
4. Вычисляет все метрики (ratio, gap, feasibility)
5. Возвращает `ExperimentResult` со всеми результатами

**`run_experiment_series(config: ExperimentConfig)`** — запуск всех экземпляров для одной конфигурации:
1. Цикл по `num_instances` экземплярам
2. Для каждого запускает `run_single_experiment()`
3. Собирает список `ExperimentResult`

**`summarize_results(results: List[ExperimentResult])`** — глобальная статистика по всем экспериментам:
- Средний, минимальный, максимальный ratio
- Средний зазор (gap)
- Процент допустимых решений

**`summarize_results_by_configuration(all_results: List[ExperimentResult])`** — статистика, сгруппированная по конфигурациям (n, m, density, profit_type, alpha)

## Метрики качества

### Коэффициент приближения (Approximation Ratio)

```
R = profit_greedy / profit_exact
```

- **Диапазон:** 0 < R ≤ 1
- **Интерпретация:**
  - R = 1: жадный нашёл оптимум
  - R = 0.5: жадный нашёл решение стоимостью 50% от оптимума
  - R близко к 0: жадный работает плохо на этом примере

### Абсолютный зазор (Profit Gap)

```
Δ = profit_exact - profit_greedy
```

- **Единицы:** те же, что и прибыль (отвлечённые единицы)
- **Интерпретация:** на сколько единиц прибыли жадный отстаёт от оптимума

### Относительный зазор (Relative Gap)

```
δ = Δ / profit_exact = (profit_exact - profit_greedy) / profit_exact
```

- **Диапазон:** 0 ≤ δ ≤ 1
- **Интерпретация:** δ · 100% — процентное отставание жадного от оптимума

### Допустимость (Feasibility)

Флаг, проверяющий, соблюдены ли все ограничения:
```
is_feasible = все (used[j] ≤ b[j] для j = 1..m)
```

Жадный алгоритм в реализации проекта всегда добавляет только допустимые предметы, поэтому его решения всегда допустимы.

## Процесс генерации данных

### Матрица потребления (A)

1. Генерируется матрица A размером m × n с целыми числами в диапазоне [1, 10]
2. Если density = "sparse":
   - Случайная выборка элементов матрицы (с вероятностью ~50%) обнуляется
   - Редкая матрица моделирует ситуацию, когда каждый ресурс потребляют далеко не все предметы

### Вектор ёмкостей (b)

```
b[j] = max(1, floor(α · Σ(i=1 to n) A[j][i]))
```

где α ∈ {0.3, 0.8}:
- **α = 0.3** — жёсткие ограничения (ёмкость составляет 30% от суммарного потребления)
  - Много предметов не поместятся
  - Жадный алгоритм вынужден тщательнее выбирать
  - Ожидается больший зазор между жадным и оптимумом

- **α = 0.8** — мягкие ограничения (ёмкость составляет 80% от суммарного потребления)
  - Больше предметов поместится
  - Жадный алгоритм имеет больше свободы
  - Ожидается меньший зазор между жадным и оптимумом

### Вектор прибылей (c)

Три стратегии генерации (моделирующие разные сценарии):

1. **random** — прибыли генерируются независимо от потребления ресурсов
   - Случайные целые числа в диапазоне [1, 100]
   - Нейтральный тестовый случай

2. **correlated** — высокоприбыльные предметы требуют много ресурсов
   - `c[i] = base + noise + 2 · (Σ(j) A[j][i])`
   - Благоприятный случай для жадного алгоритма (жадный выбирает "тяжелые" предметы, которые и есть дорогие)
   - Ожидается высокий ratio (жадный близок к оптимуму)

3. **anticorrelated** — высокоприбыльные предметы требуют мало ресурсов
   - `c[i] = base + noise - 2 · (Σ(j) A[j][i])`
   - Сложный случай для жадного алгоритма (жадный по прибыльности выбирает "лёгкие" предметы, но они мало весят и дают мало прибыли в сумме)
   - Ожидается низкий ratio (жадный далёк от оптимума)

## Частые вопросы

### Q: Почему m ≤ 3?
**A:** Точный алгоритм (ДП) имеет сложность O(n · ∏ b[j]). При MAX_WEIGHT=5 и m=3 пространство состояний ≈ 14K — быстро. При m=5 — ≈ 8M состояний на задачу, что при 1080 экспериментах занимает слишком много времени. Ограничение m ≤ 3 — компромисс между охватом и временем расчёта.

### Q: Почему n ≤ 10?
**A:** Диапазон n=5..10 достаточен, чтобы проследить зависимость α_mn(n) по теоретической формуле из статьи Чиркова–Золотых. При больших n DP-таблица растёт пропорционально n, а не экспоненциально (в отличие от перебора).

### Q: Почему именно эти параметры?
**A:** Выбор параметров обеспечивает полное покрытие интересных случаев:
- Разные размеры задач (n = 5..10)
- Разные уровни многомерности (m = 1, 2, 3)
- Разные степени сложности для жадного алгоритма (anticorrelated — наихудший, correlated — наилучший)
- Разные уровни тугости ограничений (α = 0.3 жёсткие, 0.8 мягкие)

### Q: Сколько времени займёт запуск?
**A:** При 1080 экспериментах — 1–5 минут на стандартном ПК. Можно сократить, уменьшив NUM_INSTANCES в config.py.

### Q: Как модифицировать параметры?
**A:** Отредактировать `config.py`:
- Изменить списки `N_VALUES`, `M_VALUES`, и т. д.
- Изменить `NUM_INSTANCES` (сейчас 5)
- Изменить `RANDOM_SEED` для других наборов данных

### Q: Как добавить новый алгоритм?
**A:** 
1. Создать функцию `solve_new_algorithm(instance: KnapsackInstance) -> KnapsackSolution` в новом модуле или в существующем
2. Обновить `run_single_experiment()` в `experiment.py` для запуска нового алгоритма
3. Добавить новые метрики сравнения в `metrics.py` и `visualization.py`

## Теоретическая основа

**Ключевая теорема (Чирков, Золотых):**

Гарантированная точность α_mn приближённого алгоритма для многомерной целочисленной задачи о ранце вычисляется по формуле:

```
n = m·q + r  (деление n на m с остатком, 0 ≤ r < m)

α_mn = α_{1q} / ( m + r · (α_{1q}/α_{1,q+1} − 1) )
```

где α_{1n} = δ_n/σ_n определяется рекуррентно:
```
δ_n = δ_{n-1}·(δ_{n-1} + 1),  δ_1 = 1
σ_n = 1 + σ_{n-1}·(δ_{n-1} + 1),  σ_1 = 1
```

**При больших n/m:** α_mn ≈ α_{1n}/m,  lim α_{1n} ≈ 0.5914

**Цель вычислительного эксперимента:** проверить, насколько экспериментально наблюдаемый ratio приближается к теоретической границе α_mn.
