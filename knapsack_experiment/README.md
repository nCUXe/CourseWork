# Вычислительный эксперимент: жадный алгоритм в задаче о рюкзаке

Дипломная работа, посвящённая исследованию качества жадного (greedy) алгоритма как приближённого метода решения многомерной (многоограничительной) задачи целочисленного рюкзака. Проект автоматизирует процесс генерации тестовых задач, запуска алгоритмов, вычисления метрик приближения и построения аналитических графиков.

---

## Постановка задачи

### Многомерная целочисленная задача о ранце

> **Источник:** Chirkov, Gribanov, Zolotykh. "On the Proximity of the Optimal Values of the Multi-Dimensional Knapsack Problem with and without the Cardinality Constraint". arXiv:2004.08589v1 (2020).

Дана совокупность:
- **n** типов предметов
- **m** ресурсных ограничений
- Матрица **A ∈ Z+^{m×n}**, где `A[j][i]` — расход ресурса j на одну единицу предмета i
- Вектор **b ∈ Z+^m**, где `b[j]` — ёмкость ресурса j
- Вектор **c ∈ Z+^n**, где `c[i]` — прибыль от одной единицы предмета i
- Переменные `x[i] ∈ Z+` — сколько единиц предмета i взять (0, 1, 2, ...)

### Целевая функция

Максимизировать общую прибыль:
```
max cx = max Σ(i=1 to n) c[i] · x[i]
```

При ограничениях:
```
x ∈ L(A, b) = { x ∈ Z+^n : Ax ≤ b }
```

то есть: `Σ(i=1 to n) A[j][i] · x[i] ≤ b[j]`  для всех j = 1..m

### Отличие от задачи 0–1

В задаче 0–1 каждый предмет берётся не более одного раза: `x[i] ∈ {0, 1}`.
В **целочисленном** варианте каждый тип предмета можно взять **любое неотрицательное** целое количество раз.

### Сложность

Задача является **NP-сложной** уже при m=1. С ростом m и n точное решение становится вычислительно неприемлемым. Гарантированная точность приближённого алгоритма α_mn исследована в статье Чирков–Золотых.

## Рассматриваемые алгоритмы

### 1. Приближённый алгоритм (статья Чиркова–Золотых)

**Идея:** для каждого типа предмета j определить точку v_j из L(A, b) — решение, в котором берётся только предмет j в максимально возможном количестве. Из всех таких точек выбрать ту, что даёт наибольшую прибыль.

**Максимальное количество единиц предмета j (при взятии только его):**
```
u_j = min_{i: A[i][j] > 0} floor(b[i] / A[i][j])
```

**Ценность точки v_j:**
```
cv_j = c[j] · u_j
```

**Приближённое решение:**
```
j* = argmax_j { c[j] · u_j }
x[j*] = u_{j*},  x[i] = 0  для i ≠ j*
```

**Алгоритм:**
1. Для каждого предмета j вычислить u_j и ценность c[j] · u_j
2. Выбрать предмет j* с максимальной ценностью
3. Вернуть решение: взять u_{j*} единиц предмета j*, остальные — 0

**Сложность:** O(n · m) — для каждого из n предметов проверяем m ресурсных ограничений.

**Гарантированная точность:** значение α_mn = α_{1q} / (m + r(α_{1q}/α_{1,q+1} − 1)), где n = mq + r (теорема 1 из статьи). При больших n/m: α_mn ≈ α_{1∞}/m, где lim α_{1∞} ≈ 0.591355.

---

### 2. Точное решение (Динамическое программирование)

**Идея:** ДП по оставшимся ёмкостям ресурсов. Состояние — кортеж оставшихся ёмкостей; переход — взять одну единицу любого подходящего предмета.

**Рекуррентное соотношение:**
```
dp(r) = max_{j: A[:,j] ≤ r} ( c[j] + dp(r − A[:,j]) )
dp((0,...,0)) = 0
```
где r = (r_0,...,r_{m-1}) — вектор оставшихся ёмкостей.

**Алгоритм (top-down с мемоизацией):**
1. Рекурсивно вычислить dp(b) с кешированием по словарю memo[tuple(r)]
2. Восстановить решение: трассировка через memo из состояния b вниз

**Сложность:** O(n · ∏ b[j]) в худшем случае.

**Применение в эксперименте:** точное решение служит **эталоном (ground truth)** для вычисления коэффициента приближения. Применимо при малых значениях b (достигается параметром MAX_WEIGHT=3 в config.py).

## Основные компоненты

### [models.py](src/models.py)

**`KnapsackInstance`** — представление одной задачи о рюкзаке:
- `n: int` — количество предметов
- `m: int` — количество ограничений
- `A: List[List[int]]` — матрица потребления ресурсов размером m × n
- `b: List[int]` — вектор ёмкостей ресурсов размером m
- `c: List[int]` — вектор прибылей размером n
- Методы валидации и вспомогательные функции

**`KnapsackSolution`** — решение задачи:
- `algorithm_name: str` — имя алгоритма ("greedy" или "exact_dp")
- `x: List[int]` — вектор количеств длины n: `x[i]` = сколько единиц предмета i взято
- `total_profit: int` — общая прибыль решения
- `used_resources: List[int]` — использованные объёмы каждого ресурса
- `is_feasible: bool` — допустимо ли решение (соблюдены все ограничения)

---

### [generator.py](src/generator.py)

Генерирует случайные экземпляры задач о рюкзаке с контролируемыми характеристиками.

**`generate_instance(n, m, density, profit_type, alpha, seed)`**

Параметры:
- `n` — количество предметов
- `m` — количество ограничений
- `density` — плотность матрицы A ("dense" или "sparse"). "sparse" означает, что часть элементов матрицы обнулена случайно.
- `profit_type` — тип генерации прибылей:
  - `"random"` — прибыли не коррелируют с потреблением ресурсов (нейтральный случай)
  - `"correlated"` — высокоприбыльные предметы требуют много ресурсов (благоприятный случай для жадного)
  - `"anticorrelated"` — высокоприбыльные предметы требуют мало ресурсов (сложный случай для жадного)
- `alpha` — коэффициент тугости ограничений (0 < α ≤ 1):
  - α = 0.3 — жёсткие ограничения (мало места для предметов)
  - α = 0.8 — мягкие ограничения (много места)

Процесс:
1. Генерируется матрица A (целые случайные числа в диапазоне [1,3], затем опционально прореживается)
2. Вычисляются ёмкости: `b[j] = max(1, floor(α · Σ(i) A[j][i]))`
3. Генерируются прибыли в зависимости от profit_type:
   - **random:** `c[i] ∈ [1, 100]` независимо
   - **correlated:** `c[i] = Σ(j) A[j][i] + noise`
   - **anticorrelated:** `c[i] = (max_sum + 10) − Σ(j) A[j][i] + noise`

---

### [greedy.py](src/greedy.py)

Реализует приближённый алгоритм из статьи Чиркова–Золотых. Функция `solve_greedy(instance)` вычисляет `u_j = max_count_for_item(j)` для каждого предмета, выбирает j* = argmax(c[j] · u_j) и возвращает `KnapsackSolution` с `x[j*] = u_{j*}`.

---

### [exact.py](src/exact.py)

Реализует точное решение методом динамического программирования (top-down с мемоизацией). Функция `solve_exact_dp(instance)` заполняет таблицу `memo[tuple(remaining)] = max_profit` и восстанавливает решение трассировкой. Предварительно фильтрует valid_items (исключает нулевые столбцы в A) для предотвращения бесконечной рекурсии на разреженных матрицах. Возвращает `KnapsackSolution` с максимальной прибылью.

---

### [metrics.py](src/metrics.py)

Вычисляет метрики качества приближения:

- **`approximation_ratio(greedy_profit, exact_profit)`** — отношение `R = greedy_profit / exact_profit`
  - Всегда R ≤ 1 (жадный ≤ оптимум)
  - R = 1 → жадный нашёл оптимум
  - R близко к 0 → плохое приближение

- **`profit_gap(exact_profit, greedy_profit)`** — абсолютный зазор `Δ = exact_profit - greedy_profit`
  - На сколько единиц прибыли жадный отстаёт от оптимума

- **`relative_profit_gap(exact_profit, greedy_profit)`** — относительный зазор `δ = Δ / exact_profit`
  - Процентное выражение: `δ · 100%`

- **`is_solution_feasible(instance, solution)`** — проверка допустимости решения

---

### [theory.py](src/theory.py)

Реализует точные теоретические формулы из статьи Чирков–Золотых для вычисления гарантированной точности α_mn.

**Ключевые функции:**

- **`alpha_1q(q: int) -> float`** — коэффициент α_{1q} = δ_q / ε_q для одномерной задачи с n=q
  - Вычисляется по рекуррентным формулам:
    ```
    δ_n = δ_{n-1} · (δ_{n-1} + 1),  δ_1 = 1
    ε_n = 1 + ε_{n-1} · (δ_{n-1} + 1),  ε_1 = 1
    ```
  - Значения: α_1 = 1.0, α_2 ≈ 0.667, α_3 = 0.6, α_4 ≈ 0.591549, ..., α_∞ ≈ 0.591355

- **`guaranteed_ratio(m: int, n: int) -> float`** — точная гарантированная точность α_mn по формуле (2) теоремы 1:
  ```
  n = m·q + r  (деление с остатком)
  α_mn = α_{1q} / (m + r · (α_{1q}/α_{1,q+1} − 1))
  ```

- **`asymptotic_bound(m: int) -> float`** — асимптота α_{1∞} / m при n → ∞

Используется для добавления теоретических кривых на графики spread (accuracy_spread_m_*.png).

### [experiment.py](src/experiment.py)

Определяет логику проведения экспериментов.

**`ExperimentConfig`** — параметры одной серии экспериментов:
- `n, m, density, profit_type, alpha` — параметры генерации
- `num_instances` — количество экземпляров задач для этой конфигурации

**`run_single_experiment(config: ExperimentConfig, instance_id: int)`** — запуск одного эксперимента:
1. Генерирует один экземпляр задачи
2. Запускает жадный алгоритм
3. Запускает точный алгоритм
4. Вычисляет все метрики (ratio, gap, is_optimal)
5. Возвращает `ExperimentResult` со всеми результатами

**`run_experiment_series(config: ExperimentConfig)`** — запуск всех экземпляров для одной конфигурации:
1. Цикл по `num_instances` экземплярам
2. Для каждого запускает `run_single_experiment()`
3. Собирает список `ExperimentResult`

**`summarize_results(results: List[ExperimentResult])`** — глобальная статистика по всем экспериментам:
- Средний, минимальный, максимальный ratio
- Средний зазор (gap)
- Количество точных решений (is_optimal count) и exact_rate (доля)

**`summarize_results_by_configuration(all_results: List[ExperimentResult])`** — статистика, сгруппированная по конфигурациям (n, m, density, profit_type, alpha)

### Итого

- **Конфигураций:** 7 × 3 × 2 × 3 × 2 = **252**
- **Экземпляров:** 252 × 30 = **7560**
- **Каждый эксперимент включает:** генерацию задачи, запуск жадного алгоритма, запуск точного алгоритма (ДП), вычисление всех метрик

## Метрики качества

### Коэффициент приближения (Approximation Ratio)

```
R = profit_greedy / profit_exact
```

- **Диапазон:** 0 < R ≤ 1
- **Интерпретация:**
  - R = 1: жадный нашёл оптимум (is_optimal = true)
  - R = 0.5: жадный нашёл решение стоимостью 50% от оптимума
  - R близко к 0: жадный работает плохо на этом примере

### Точность (Exact Rate)

```
exact_rate = (число экземпляров где R = 1.0) / (общее число экземпляров)
```

- **Диапазон:** 0 ≤ exact_rate ≤ 1
- **Интерпретация:** доля случаев, где жадный алгоритм нашёл оптимальное решение

### Абсолютный зазор (Profit Gap)

```
Δ = profit_exact - profit_greedy
```

- **Интерпретация:** на сколько единиц прибыли жадный отстаёт от оптимума

### Относительный зазор (Relative Gap)

```
δ = Δ / profit_exact = (profit_exact - profit_greedy) / profit_exact
```

- **Диапазон:** 0 ≤ δ ≤ 1
- **Интерпретация:** δ · 100% — процентное отставание жадного от оптимума

### Допустимость (Feasibility)

Флаг, проверяющий, соблюдены ли все ограничения. Жадный алгоритм в реализации проекта всегда добавляет только допустимые предметы, поэтому его решения всегда допустимы.

## Процесс генерации данных

### Матрица потребления (A)

1. Генерируется матрица A размером m × n с целыми числами в диапазоне [1, 3]
2. Если density = "sparse":
   - Случайная выборка элементов матрицы (с вероятностью ~50%) обнуляется
   - Редкая матрица моделирует ситуацию, когда каждый ресурс потребляют далеко не все предметы

### Вектор ёмкостей (b)

```
b[j] = max(1, floor(α · Σ(i=1 to n) A[j][i]))
```

где α ∈ {0.3, 0.8}:
- **α = 0.3** — жёсткие ограничения (ёмкость составляет 30% от суммарного потребления)
- **α = 0.8** — мягкие ограничения (ёмкость составляет 80% от суммарного потребления)

### Вектор прибылей (c)

Три стратегии генерации (моделирующие разные сценарии):

1. **random** — прибыли генерируются независимо: `c[i] ∈ [1, 100]`
2. **correlated** — высокоприбыльные предметы требуют много ресурсов: `c[i] = Σ(j) A[j][i] + noise`
3. **anticorrelated** — высокоприбыльные предметы требуют мало ресурсов: `c[i] = (max_sum + 10) − Σ(j) A[j][i] + noise`

Этот раздел содержит детальный анализ полученных результатов из 7560 экспериментов, объясняет ключевые закономерности и выявляет подкласс задач, где жадный алгоритм наиболее эффективен.

### A. Главный результат: подкласс эффективности (m=1)

**Ключевое наблюдение:** число ресурсных ограничений **m** является доминирующим фактором, определяющим качество жадного алгоритма.

| m | Средний ratio | Min ratio | Max ratio | Exact rate |
|---|---|---|---|---|
| 1 | **0.995** | 0.667 | 1.000 | **0.946** (94.6%) |
| 2 | 0.871 | 0.462 | 1.000 | 0.422 (42.2%) |
| 3 | 0.819 | 0.324 | 1.000 | 0.312 (31.2%) |

**Вывод:** При m=1 (одно ресурсное ограничение) жадный алгоритм работает почти оптимально:
- средний коэффициент приближения 0.995 (всего 0.5% хуже оптимума в среднем)
- в 94.6% случаев находит *точный* оптимум (ratio = 1.0)
- монотонное снижение качества с ростом m согласуется с теоретической оценкой α_mn ∝ 1/m

**Лучший узкий подкласс:** **m=1, anticorrelated, dense**
- среднее ratio ≈ 1.000 (практически всегда оптимум)
- обоснование: антикоррелированная прибыль (дорогие предметы лёгкие) + полная матрица A делает "один лучший предмет" почти всегда оптимальным решением

**Практический вывод для диплома:** при одномерности (m=1) задача фактически становится классической задачей о рюкзаке, где берут один предмет в максимальном количестве — а это часто и является оптимумом. Это основной найденный подкласс эффективности.

### B. Неожиданный результат: profit_type слабо влияет в среднем, но сильно в подклассах

**Глобальный анализ:**

| profit_type | Средний ratio | Min ratio |
|---|---|---|
| correlated | 0.897 | 0.333 |
| anticorrelated | 0.895 | 0.352 |
| random | 0.893 | 0.324 |

**Вывод:** В среднем по всем m разница минимальна (0.893–0.897). **Исходная гипотеза, что anticorrelated наихудший, не подтвердилась в глобальном среднем.**

**Однако внутри подклассов эффект очень сильный:**

- **При m=1:** anticorrelated лучший (avg ≈ 1.000, exact_rate 95%+), correlated содержит наихудший min_ratio (0.667 для dense)
- **При m=3:** все типы близки в среднем (0.81–0.82), но min_ratio anticorrelated=0.352, correlated=0.333, random=0.324

**Обоснование:** для целочисленного (unbounded) рюкзака с алгоритмом "один предмет":
- Когда дорогие предметы также лёгкие (anticorrelated), они выигрывают на фактор цены и минимальной пропускной способности — "один лучший" часто совпадает с оптимумом
- Когда дорогие предметы тяжелые (correlated), жадный выбирает их, но иногда смешение нескольких лёгких может быть лучше
- Random промежуточный

**Усреднение по m маскирует эффект:** при m≥2 все типы становятся близкими, что размывает структуру в глобальном среднем.

### C. Плотность матрицы A — второй по силе фактор

| Плотность | Средний ratio | Min ratio |
|---|---|---|
| dense | **0.944** | 0.333 |
| sparse | **0.846** | 0.324 |

**Разница:** 0.944 − 0.846 = 0.098 (9.8 п.п.) — значительный эффект, хотя меньше, чем эффект m.

**Обоснование разницы:**

- **Dense матрица:** каждый предмет потребляет все ресурсы. Жадный выбирает "один лучший", который обеспечивает хороший баланс по всем ограничениям → решение часто близко к оптимуму
- **Sparse матрица:** нулевые элементы означают, что каждый предмет имеет разный "профиль" потребления. Оптимальное решение выигрывает от **смешения предметов** с дополняющими профилями (заполнить разные ресурсы разными предметами). Жадный берёт только один → большой зазор.

**Худший подкласс:** **m=3, sparse, random** с min_ratio = 0.324, avg_ratio = 0.720
- Обоснование: максимальная многомерность (m=3), максимальная разреженность, случайная прибыль (без структуры в пользу одного предмета)

### D. Тугость ограничений (alpha)

| alpha | Средний ratio |
|---|---|
| 0.3 (жёсткие) | **0.910** |
| 0.8 (мягкие) | **0.880** |

**Разница:** 0.910 − 0.880 = 0.030 (3 п.п.) — слабый, но устойчивый эффект.

**Обоснование:**
- **Жёсткие (α=0.3):** ёмкость рюкзака мала → в него влезает мало единиц → решение "одного предмета в максимальном количестве" имеет высокую вероятность совпадения с оптимумом (добавление ещё предметов часто невозможно)
- **Мягкие (α=0.8):** ёмкость велика → в рюкзак влезает много → оптимум может выгодно использовать комбинацию предметов, а жадный берёт только один → больший зазор

Коэффициент приближения слегка убывает с ростом n от 5 к 12:

- При n=12: avg_ratio ≈ 0.888

### F. Эксперимент vs теория: почему практика >> worst-case

**Теоретический bound (из формулы α_mn статьи):**

| m | Асимптота α_{1∞}/m при n→∞ | α_m5 (точно) | α_m12 (точно) |
|---|---|---|---|
| 1 | 0.591 | 1.000 | 0.991 |
| 2 | 0.296 | 0.500 | 0.495 |
| 3 | 0.197 | 0.333 | 0.330 |

**Экспериментальные результаты (среднее по всем конфигам):**

| m | Теоретический bound | Экспериментальное среднее | Экспериментальный минимум |
|---|---|---|---|
| 1 | 0.591–1.0 | **0.995** | 0.667 |
| 2 | 0.296–0.500 | **0.871** | 0.462 |
| 3 | 0.197–0.333 | **0.819** | 0.324 |

**Наблюдение:** даже **минимальный ratio** (0.324 при m=3) существенно **выше** теоретической асимптоты (0.197), а **среднее** ещё дальше отстоит.

**Ключевой анализ — почему это нормально:**

α_mn из статьи — это **инфимум** (наихудший гарантированный ratio) по **всем возможным** экземплярам задач с заданными m, n. Граница достигается (или близка к достижению) только на специально сконструированных "adversarial" задачах.

**Конструкция worst-case (Лемма 5 статьи):** прямое произведение одномерных задач с весами в специальных пропорциях:
```
δ_1=1, δ_2=2, δ_3=6, δ_4=42, δ_5=1806, ...
```

При MAX_WEIGHT=3 такие пропорции **невозможны** — максимальное отношение весов всего 3. Поэтому:
- Случайно сгенерированные задачи структурно **далеко** от worst-case
- Экспериментальные результаты много лучше теоретической границы

**Это классический разрыв between worst-case и average-case анализа.**

Проверка теории: значения α_1q из `src/theory.py` по формуле δ_n/ε_n точно совпадают с Таблицей 1 статьи Чирков–Золотых: α_1=(1.0), α_2≈(0.667), α_3=(0.6), α_4≈(0.591549), ..., α_∞≈(0.591355) ✓

---

### G. Итоговая формулировка для защиты диплома

**Теоретический результат статьи Чирков–Золотых:**
Жадный алгоритм гарантирует приближение не менее α_mn, которое убывает как α_mn ~ α_{1∞}/m ≈ 0.591/m при больших n.

**Экспериментальные результаты (7560 экспериментов):**
1. На случайных задачах среднее качество **намного лучше** теоретической границы:
   - Глобальный средний ratio: **0.895** (vs теоретической асимптоты для m=1.5: ~0.39)
   - При m=1: **0.995** (vs теоретической асимптоты: 0.591)
   
2. Найден **подкласс эффективности**: **m=1 (одно ресурсное ограничение)**
   - Средний ratio: 0.995
   - Доля точных решений (exact_rate): **94.6%**
   - При дополнительных условиях (anticorrelated, dense): ratio ≈ 1.000

3. **Дополнительные факторы улучшения:**
   - Dense матрица (0.944 vs 0.846 для sparse) — улучшает на 9.8 п.п.
   - Жёсткие ограничения (0.910 vs 0.880) — улучшают на 3 п.п.
   - Слабое влияние: anticorrelated в среднем, но помогает в подклассах

4. **Объяснение разрыва between теорией и практикой:**
   - Worst-case (α_mn) достигается только на "adversarial" задачах с весами вроде 1:2:6:42:1806:…
   - Случайные задачи с MAX_WEIGHT=3 не могут достичь таких пропорций
   - Это стандартный разрыв worst-case vs average-case

**Практический вывод:**
Жадный алгоритм из статьи Чиркова–Золотых рекомендуется для практического применения при m=1 (классический одномерный рюкзак), где он находит оптимум в 94.6% случаев. На случайных многомерных задачах (m≥2) результаты значительно лучше теоретической гарантии, но хуже, чем при m=1.

## Частые вопросы

### Q: Почему m ≤ 3?
**A:** Точный алгоритм (ДП) имеет сложность O(n · ∏ b[j]). При MAX_WEIGHT=3 и m=3 пространство состояний ≈ 27K — быстро. При m=5 — ≈ 243K состояний на задачу, что при 7560 экспериментах занимает слишком много времени. Ограничение m ≤ 3 — компромисс между охватом и временем расчёта.

### Q: Почему n доходит до 12?
**A:** Диапазон n=5..12 позволяет проследить зависимость α_mn(n) по теоретической формуле из статьи Чирков–Золотых. n=12 — достаточно для наблюдения асимптотического поведения без чрезмерного роста DP-таблицы.

### Q: Почему MAX_WEIGHT=3?
**A:** Веса A[j][i] ∈ [1,3] держат пространство состояний DP в пределах 27K на конфигурацию, позволяя быстро вычислять точные решения. Большие веса экспоненциально увеличивают время DP, малые — снижают интересность задачи.

### Q: Почему NUM_INSTANCES=30?
**A:** 30 экземпляров на конфигурацию обеспечивают статистическую надёжность (ошибка среднего ~6–10%). Было: 5 экземпляров (ошибка ~20%). Увеличение до 30 даёт хорошую статистику при приемлемом времени выполнения.

### Q: Сколько времени займёт запуск?
**A:** При 7560 экспериментах на современном ПК — 5–15 минут. Можно сократить, уменьшив NUM_INSTANCES в config.py.

### Q: Как модифицировать параметры?
**A:** Отредактировать `config.py`:
- Изменить списки `N_VALUES`, `M_VALUES`, и т. д.
- Изменить `NUM_INSTANCES` (сейчас 30)
- Изменить `MAX_WEIGHT` (сейчас 3)

## Теоретическая основа

**Ключевая теорема (Chirkov, Gribanov, Zolotykh, 2020):**

Гарантированная точность α_mn приближённого алгоритма для многомерной целочисленной задачи о ранце вычисляется по формуле (2) из статьи:

```
n = m·q + r  (деление n на m с остатком, 0 ≤ r < m)

α_mn = α_{1q} / ( m + r · (α_{1q}/α_{1,q+1} − 1) )
```

где α_{1n} = δ_n/ε_n определяется рекуррентно:
```
δ_n = δ_{n-1} · (δ_{n-1} + 1),  δ_1 = 1
ε_n = 1 + ε_{n-1} · (δ_{n-1} + 1),  ε_1 = 1
```

**Асимптотическое поведение:**
```
lim α_{1n} = 0.591355492056890... (при n → ∞)
α_mn → α_{1∞} / m  (при n → ∞, m фиксировано)
```

**Реализация в проекте:** `src/theory.py` вычисляет эти значения точно и добавляет теоретические кривые на графики spread.

**Цель вычислительного эксперимента:** проверить, насколько экспериментально наблюдаемый ratio на случайных задачах соотносится с теоретической границей α_mn.
